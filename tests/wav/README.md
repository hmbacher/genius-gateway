# SmartSonic Test WAV Files

Synthetic audio files for manual testing of the Genius Gateway acoustic readout decoder.
Generated by `tests/generate-smartsonic-wav.mjs` — re-run to regenerate.

All files encode a **Genius Plus X** smoke detector. Most pair it with an **FM.Basis X**
radio module; `sd-no-radio.wav` has no radio module, and `sd-genius-plus-x-fm-basis.wav`
pairs it with an **old-generation FM.Basis** module (see that file's section below).

## How to use

1. Open the Genius Gateway UI over **HTTPS** and navigate to the smoke detectors page.
2. Click **Acoustic Device Detection** or the per-device **Update** (readout) button.
3. Play the WAV file through a speaker placed near the browser's active microphone.
4. The decoder should lock sync, decode the frame, and surface the data in the UI.

## Signal encoding

All files use **PATTERN_SET_1** (SYNC1, symbolLen = 65.708):

| Parameter | Value |
|---|---|
| Sample rate | 44 100 Hz, 16-bit mono |
| NCO centre frequency | 4 449.1 Hz |
| FSK deviation (Δf) | ±250 Hz around NCO |
| Decimation | 8× → 5 512.5 Hz effective |
| Error correction | Hamming(8,4) |
| Framing | `[length][payload…][CRC-16 lo][CRC-16 hi]` |
| CRC-16 | poly 0x8005, init 0xFFFF, over payload only |
| Signal amplitude | 0.70 (of full scale) |
| Silence pre/post | ~0.40 s |

## Payload byte map

All payloads are 32 bytes (all include FM.Basis X radio module data, `radioProductType > 0`).

| Byte(s) | Field |
|---|---|
| 0 | Protocol version |
| 1–4 | SD serial number (big-endian) |
| 5 | `productType [3:0]` \| `radioProductType [7:4]` |
| 6 | Deinstallation count |
| 7 | Alarm count total |
| 8 | Alarm count last 3 months |
| 9–10 | Last alarm offset in days from production (LE); 0xFFFF = never |
| 11–12 | Production age in days (LE) |
| 13–14 | Hours in storage mode (LE) |
| 15–16 | Last self-test offset in days from production (LE); 0xFFFF = never |
| 17–18 | Warranty flags bitmask (LE) |
| 19 | Device status byte |
| 20 | Radio state mask |
| 21–24 | Radio module serial number (big-endian) |
| 25–28 | Alarm line ID (big-endian) |
| 29 | `lineCharIdx [7:4]` \| `lineNumber [3:0]` |
| 30 | Radio switch flags |
| 31 | Radio interference in 0.1 dB units |

## Device status byte (byte 19) bit map

| Bit | Mask | Field |
|---|---|---|
| 0 | `0x01` | `batteryLowFault` |
| 1 | `0x02` | `deviceFault` |

| 3–6 | `0x78` | `driftState` (0–7; 0 = OK, 2 = warning, 4 = defect) |
| 7 | `0x80` | `dirtForecastNegative` |

## sd-genius-plus-x-fm-basis.wav — Genius Plus X + FM.Basis (old module)

**SD:** Genius Plus X · SN `0x12A1000C` · age ~1 year
**RM:** FM.Basis (old, `radioProductType=1`) · SN `0xAB00100C`

Pairs a current-generation smoke detector with an **old-generation** radio module
(FM.Basis). Old modules cannot expose a trustworthy alarm line: they always
transmit `lineId=0`, and the line byte (29) is unreliable. This file deliberately
sets byte 29 to non-zero "garbage" (`F.7`) to verify the frontend **ignores it**
and requires manual line entry regardless of what's on the wire — see
[`old-fm-manual-line-entry.md`](../../old-fm-manual-line-entry.md).

### Fields

| Byte(s) | Hex | Dec | Field | Value |
|---|---|---|---|---|
| 0 | `05` | 5 | Protocol version | 5 |
| 1–4 | `12 A1 00 0C` | — | SD serial number | 0x12A1000C |
| 5 | `13` | 19 | Product types | SD=3 (Genius Plus X), RM=1 (FM.Basis) |
| 6 | `00` | 0 | Deinstallation count | 0 |
| 7 | `00` | 0 | Alarm count total | 0 |
| 8 | `00` | 0 | Alarm count last 3 months | 0 |
| 9–10 | `FF FF` | 65535 | Last alarm offset (days) | Never |
| 11–12 | `6D 01` | 365 | Production age (days) | ~1 year |
| 13–14 | `00 00` | 0 | Hours in storage | 0 |
| 15–16 | `4A 01` | 330 | Last self-test offset (days) | 330 days after production |
| 17–18 | `00 00` | 0 | Warranty flags | 0 — intact |
| 19 | `00` | 0 | Device status byte | all clear |
| 20 | `00` | 0 | Radio state mask | all clear |
| 21–24 | `AB 00 10 0C` | — | RM serial number | 0xAB00100C |
| 25–28 | `00 00 00 00` | 0 | Line ID | 0 — old modules always transmit 0 |
| 29 | `57` | — | Line char/number | **untrusted** — decodes as F.7 (charIdx=5, lineNum=7) but must not be used |
| 30 | `18` | 24 | Radio switch flags | RadioLinkSupervision + ReceiveCollectiveAlarm |
| 31 | `04` | 4 | Radio interference | 0.4 dB |

### Raw payload (32 bytes)

```
05 12 a1 00 0c 13 00 00 00 ff ff 6d 01 00 00 4a 01 00 00 00 00 ab 00 10 0c 00 00 00 00 57 18 04
```

**CRC-16:** `0xC4B6` · Frame: 35 bytes

### Expected behavior

The decoder parses the frame normally (it's protocol-agnostic), but the application
layer must treat the old module's line fields as unusable:

```
sdSerialNumber:        0x12A1000C
sdModel:               3  (Genius Plus X)
rmSerialNumber:        0xAB00100C
rmModel:               1  (FM.Basis — OLD)
productionAgeDays:     365
radioStateMask:        0x00
lineId:                0          (always 0 for old modules)
lineChar / lineNumber: 'F' / 7    (present on the wire, but UNRELIABLE — must be discarded)
radioInterference:     0.4 dB
```

The frontend (`tunerDataToGeniusDevice` in `smoke-detectors/+page.svelte`) must drop
`lineId`/`lineCharacter`/`lineNumber` for this device and mark it as needing manual
line entry — it must **not** show "F.7" anywhere.
